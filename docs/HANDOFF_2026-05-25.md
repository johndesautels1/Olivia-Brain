## § 5 — Standing rules that took new weight this session

Each of these is in `~/CLAUDE.md` or memory. This session demonstrated
why they exist; they apply with extra force going forward.

1. **"100% no breaking changes / 100% no partial coding"** — the attestation
   in every commit message. This session, that line followed a few commits
   that didn't quite earn it (the "WCAG sweep" was 7 buttons + 1 heading,
   the "APCA measurement" was a source-code approximation). The attestation
   is not a slogan; it's a claim that has to be true line-by-line.
2. **Don't substitute work-shaped activity for the harder answer.**
   When a task can't be done within the seat's capabilities (no browser,
   no real screen reader, no production DB connection), the right answer
   is to say so and stop. Not to reshape the task into something
   doable + similar-sounding.
3. **"Line by line, no lies."** The founder's exact words 2026-05-25.
   Cite file:line for every finding. Don't paraphrase. Don't infer from
   class names what colour the browser actually renders.
4. **Inline SQL migrations in chat at the moment of reference** —
   `feedback_inline_sql_migrations`. Already a standing rule. Apply
   to migration 15 (above § 3.1) every time you reference it.
5. **PowerShell `Set-Content -Encoding utf8` mangles multibyte
   characters** — this session caught it on em-dashes and box-drawing
   in comments. Use Edit `replace_all=true`, not PowerShell, for
   batch text replacements on files with non-ASCII content.
6. **Skepticism on token discoveries.** When a class like `text-fog`
   appears to have no `--color-fog` token, the simpler explanation
   is usually "the resolution path isn't where I'm looking," not
   "73 production occurrences are broken." Verify before refactoring.
